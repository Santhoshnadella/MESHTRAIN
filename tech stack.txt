# MeshTrain — Complete Tech Stack

The stack should stay **lightweight, P2P-first, modular, and decentralized**. The key rule is that no cloud service, central database, or central GPU cluster is required to run MeshTrain.

## 1. Core Language

| Layer                | Technology           | Purpose                                                                       |
| -------------------- | -------------------- | ----------------------------------------------------------------------------- |
| Primary              | **Python 3.11+**     | Core framework, AI orchestration                                              |
| Performance-critical | **Rust**             | P2P/networking, high-performance components where Python becomes a bottleneck |
| Protocol             | **Protocol Buffers** | Compact peer-to-peer messages                                                 |
| Configuration        | **TOML/YAML**        | Node and job configuration                                                    |

**Recommended approach:** start primarily in Python; introduce Rust only for proven bottlenecks.

# 3. P2P Networking

This is the most important part of MeshTrain.

```text
MeshTrain Protocol
        ↓
libp2p
        ↓
QUIC
        ↓
Internet
```

### Recommended

**libp2p**

Provides:

* peer identity
* encrypted connections
* multiplexing
* peer discovery
* DHT
* NAT traversal
* relay
* hole punching

### Transport

**QUIC**

Advantages:

* low connection overhead
* multiplexed streams
* connection migration
* good behavior on unreliable networks
* encrypted by default through QUIC/TLS

### Optional

```text
WebRTC
TCP fallback
HTTP
```

WebRTC can be useful for browser/edge participation later.

# 8. Storage

Default should be **local-first**.

```text
SQLite
+
Local Filesystem
+
Content-Addressed Storage
```

### SQLite

Stores:

* jobs
* node state
* peer metadata
* local indexes
* checkpoints
* configuration

### Content-addressed storage

Every artifact gets a hash:

```text
model
 ↓
SHA-256/content hash
 ↓
manifest
 ↓
chunks
```

This enables BitTorrent-style distribution.

### The core dependency philosophy

**Mandatory:**

```text
Python
PyTorch
FastAPI
libp2p
QUIC
Protocol Buffers
SQLite
```

**AI optional modules:**

```text
Transformers
PEFT
Accelerate
bitsandbytes
vLLM
DeepSpeed
FSDP
```

**Infrastructure optional:**

```text
Docker
S3/MinIO
IPFS
Prometheus
Grafana
```

**Frontend optional:**

```text
Next.js
React
Tailwind
React Flow
```

The most important architectural decision is that **MeshTrain itself should remain runnable with just one machine and an Internet connection**. Everything else—cloud storage, dashboards, observability stacks, centralized services, community relays—is an extension rather than a prerequisite.
